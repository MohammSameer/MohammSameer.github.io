01COMPANY · PRIVATE REPO

Solis Insurify

Insurance distribution platform · Jan 2026 – present

Private company code · details on request
OVERVIEW

An insurance distribution platform used by agents, relationship managers, operations and HR teams. It's a TypeScript monorepo of NestJS services and Next.js portals. It's a team-built platform; since January 2026 I've shipped 44 merged pull requests, 31 database migrations and 200+ test files across its KYC, policy, commission, audit and reporting domains.

OUTCOMES
  • Commission that was silently computing as ₹0 is now priced from the correct rates. I found four separate faults hiding behind each other.
  • Insurer policy PDFs now fill the policy form automatically, and low-confidence fields are flagged for review instead of guessed. Live in production.
  • Partner KYC stopped producing duplicate cases and stuck approvals, and rejected documents can be corrected without starting over.
  • Commission & payin settlement engine: rate inputs travel through events, DTOs and gRPC, and rates are pinned to the product version in force on the sale date. Re-pricing is append-only and refuses to touch paid instalments; database CHECK constraints are the last guard.
  • Layout-aware PDF extraction engine: a geometry layer (rows, cells, label/value pairs across columns) kept separate from a semantic layer that gives every field a confidence score. It shipped behind a feature flag with a capped fallback, and a golden-file test set enforces a minimum recall. 300+ tests.
  • Agent reassignment ledger: an append-only ledger that doubles as a transactional outbox to four downstream services. Idempotency keys, compare-and-swap batches, and a reconciler that repairs drift on its own.
  • KYC case lifecycle: one state model shared by two services and three portals. A partial unique index guarantees one open case per agent. Document re-linking is idempotent. Reviewer assignment is fair, and each document can be rejected separately with an append-only history.
  • Activity & audit log: each event is delivered at least once and processed exactly once (an idempotent inbox), with a dead-letter queue, payload redaction and an event-coverage test.
  • Sales attribution & lead conversion: policies are now credited to the agent who sold them, which restored 34 policies to their agents' portals. A separate "issued by the insurer" lifecycle keeps unissued business out of renewals and commission.
  • Access & onboarding: a default-deny Leads Assigner role, reporting-line scoping through one recursive-CTE resolver, employee invites on Better Auth, and fail-closed authentication between services.
  • Foundations: the KYC, claims, SLA and contest domains of the operations service; real-time support chat on Socket.IO + Redis; insurer email ticketing with HMAC-signed reply addresses.

Private company code · details on request

04PERSONAL · OPEN SOURCE

Sugam Form Filler

Multilingual AI agent for government forms

Code ↗
OVERVIEW

One wrong field can get an official form in India rejected, and the form is rarely in a language the applicant is comfortable with. Sugam is a vision-enabled, multilingual agent: it reads a photo of the form, explains every field in the user's own language, and asks one question at a time. Then it generates a filled PDF. A security checkpoint in front of the model masks personal data and blocks prompt injection.

  • Multi-agent orchestration on Google ADK: an orchestrator hands off to a vision form-reader and a conversational data collector via transfer_to_agent.
  • A security checkpoint on every model call: a before_model_callback on all three agents masks Aadhaar, PAN and bank numbers, blocks prompt injection and consent refusal, and writes a JSON audit log.
  • An MCP server with domain tools: form-field parsing, scheme lookup (from a curated offline knowledge base) and filled-PDF generation, with Devanagari and Tamil rendering.
  • Ten Indian languages: explanations, questions and messages all reply in the user's own language.

05PERSONAL · LIVE

CoinStack

Credit-card spend analytics & rewards · take-home, built end to end

Live demo ↗Code ↗
OVERVIEW

A credit-card bill-pay app: browse your transactions, see where the money goes, and turn spending into coins you can redeem. I built every layer, from the Next.js frontend through a FastAPI backend to PostgreSQL. It's deployed on Vercel, Render and Neon.

  • Messy data, nothing dropped: it loads 10,000 transactions with mixed date formats, amounts stored as strings and duplicate IDs, and shows a data-quality report in the UI.
  • Server-side everything: filtering, sorting and paging run in PostgreSQL. The charts and the table share one filter object, so clicking a chart filters the table and filtering the table updates the charts.
  • Safe redemption: redemptions are atomic and safe to retry, enforced by a unique index, with distinct status codes for every failure. The UI updates optimistically and rolls back on failure. 9 pytest tests run against a real database.
  • Hand-built UI: no component library. It includes a focus-trapped modal, a drawer, dark mode, and keyboard and screen-reader support.
  • Deployment decision: I put the API and the database in the same region, because each request makes several database round trips.
